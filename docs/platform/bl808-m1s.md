Sipeed M1s Dock
==============

The Bouffalo Lab BL808 D0 core is a single T-Head C906 hart. OpenSBI uses
UART3 on GPIO16 (TX) and GPIO17 (RX), at 2 Mbaud, 8N1. The board platform
initializes the UART clock and pads before the generic console driver runs.
The polling driver takes the register address, input clock in Hz, and baud
rate from `reg`, `clock-frequency`, and `current-speed`, respectively.

Build
-----

Build the minimal boot devicetree and an FW_JUMP image:

```sh
dtc -I dts -O dtb -o bl808-m1s.dtb docs/platform/bl808-m1s.dts
make PLATFORM=generic \
     CROSS_COMPILE=riscv64-linux-gnu- O=build/bl808 \
     FW_TEXT_START=0x3ef80000 FW_JUMP_ADDR=0x50000000 \
     FW_JUMP_FDT_ADDR=0x51ff8000 FW_DYNAMIC=n FW_PAYLOAD=n
```

The firmware is `build/bl808/platform/generic/firmware/fw_jump.bin`.
The default generic configuration also includes BL808 support.

Boot contract
-------------

The preceding D0 loader must initialize PSRAM and grant D0 access to the
512 KiB SRAM window at `0x3ef80000`. It loads OpenSBI there, U-Boot at
`0x50000000`, and the DTB at `0x51ff8000`. Enter OpenSBI in M-mode with
`a0 = 0` (hart ID) and `a1 = 0x51ff8000` (DTB address), after synchronizing
instruction fetch with the loaded image. UART initialization is not required
in the loader.

OpenSBI code, data, hart stack, and heap must fit in the reserved SRAM
window. The DTB reserves the whole window, requests a 64 KiB OpenSBI heap,
and exposes the 64 MiB PSRAM as normal memory. The loader must keep its
working memory outside this window until handoff.

The example DTB contains the devices OpenSBI needs. U-Boot must provide a
complete board DTB for Linux, preserving the OpenSBI SRAM reservation.
